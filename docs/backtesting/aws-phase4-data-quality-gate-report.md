## Scope

Phase 4 adds a pre-run data-quality gate that samples lake data before the replay engine
processes a single bar. A run is blocked entirely if any symbol has ERROR-level data issues
or comes from a LOW-trust (quarantined) source.

Phase 4 deliverables:
1. **`DataQualityGate`** — samples the first 90 days of the date range, runs all 12 quality checks, classifies symbols as blocked / warn-only / clean
2. **`GateResult`** — structured outcome with `passed`, `blocked_symbols`, `warn_only_symbols`, `markdown_report`, `report_s3_path`
3. **`BacktestRunner` integration** — `dq_gate=` parameter; gate failure marks run FAILED before any shard starts
4. **S3 report upload** — QA report written to `{results_bucket}/data-quality/{run_id}/report.md`
5. **CW `DQGateFailed` metric** — emitted on any gate failure; wired to the Phase 2 CloudWatch alarm

## Phase 4 Deliverables

### 1. DataQualityGate (`services/backtesting/data_quality_gate.py`)

```
DataQualityGate.check(spec, timeframes=["1d"]) → GateResult

  For each symbol × timeframe:
    sample_window = start_date → min(start_date + 90 days, end_date)
    path = catalog.lake_partition(symbol, interval, year=start_date.year, ...)
    df = load_candles(path, ...)
    if S3 raises → QualityResult(check="load_error", severity=ERROR)  [blocks run]
    if df.empty  → run_quality_checks() → empty_dataset ERROR          [blocks run]
    else         → run_quality_checks(df)                              [12 checks]
  
  blocked = symbols where not eligible_for_use (ERROR or quarantined)
  warn_only = symbols where passed + not quarantined + has warnings
  passed = no blocked symbols
  
  if not passed → cw_emitter.dq_gate_failed()
  Report → to_markdown() → S3 upload (non-fatal)
```

**Blocking policy:**

| Condition | Blocks run? |
|---|---|
| Any ERROR-severity quality issue | Yes |
| LOW-trust (quarantined) source | Yes |
| WARN-severity issues only | No (logged; reported) |
| Clean HIGH-trust data | No |

**Sampling rationale:** 90-day window per symbol keeps gate latency proportional to
symbol count (not run length). A 10-year run and a 1-year run have the same gate cost.

### 2. BacktestRunner Integration (`services/backtesting/runner.py`)

`BacktestRunner.run()` gains a `dq_gate: Any = None` parameter:

```
create_run(spec) → init_checkpoint(run_id)
↓
dq_gate.check(spec, timeframes=config.timeframes)
  if FAIL → registry.mark_failed(run_id, reason) → return FAILED RunSummary
  if PASS → continue
↓
CandleReplayEngine.run_with_backtester(...)  ← replay only starts if gate passes
```

Passing `dq_gate=None` (default) skips the gate entirely, preserving full backward
compatibility for tests and already-validated datasets.

### 3. CloudWatch Wiring

`DQGateFailed` metric is emitted in `BacktestCloudWatchEmitter.dq_gate_failed()` (Phase 3).
The Phase 2 CloudWatch alarm `dq-gate-failure` fires when this metric > 0 in any 5-minute
window, alerting via the SNS topic `quantembrace-backtest-alerts`.

### 4. S3 Report

When `results_bucket` is set, the gate uploads a markdown QA report to:

```
s3://{results_bucket}/data-quality/{run_id}/report.md
```

The report includes: gate verdict, per-symbol issue table (generated by `to_markdown()`),
sample window dates, and the full 12-check breakdown with severity counts.

Report upload is **non-fatal** — an S3 write failure logs a WARNING but does not block
the gate verdict or the run.

## Data Quality Checks (Pre-existing, exercised by Phase 4)

| # | Check name | Severity |
|---|---|---|
| 1 | `timezone_error` | ERROR — timestamps not IST-aware |
| 2 | `future_timestamp` | ERROR — bars dated after "now" |
| 3 | `duplicate_timestamp` | ERROR — same timestamp twice |
| 4 | `invalid_ohlc` | ERROR — high < low or close outside [low, high] |
| 5 | `non_positive_prices` | ERROR — open/high/low/close ≤ 0 |
| 6 | `zero_volume` | WARN — sessions with zero volume |
| 7 | `market_hours_violation` | WARN — bars outside NSE session hours |
| 8 | `missing_candles` | WARN — gaps within a trading day (intraday) |
| 9 | `missing_trading_days` | WARN — days absent from expected calendar |
| 10 | `outlier_price_jump` | ERROR — % change > 20% bar-to-bar |
| 11 | `symbol_mapping_gap` | WARN — no ISIN or symbol in registry |
| 12 | `corporate_action_gap` | WARN — suspicious ≥15% jump near known CA date |

`empty_dataset` (no rows loaded) is treated as an implicit ERROR in the gate: if `load_candles`
returns an empty DataFrame, `run_quality_checks` produces an `empty_dataset` ERROR that blocks
the run.
